# WebView 与宿主的二进制传输

设计基线。现有 `ctx.bytes` 和 `bridge.bytes` 用 JSON 请求读取字节。新增内存会话为 WebView 和 Rust 宿主提供双向、有界的字节传输，供文件、剪贴板和原生处理能力复用。

## 插件接口

主窗口和插件窗口共用 `binary.open(size)`，需要 `rpc:binary`。`size` 是本次会话声明的最大字节数。返回的句柄提供 `id`、`maxChunkBytes`、`write(offset, bytes)`、`read(offset, maxBytes)` 和 `close()`。

每次写入确认当前已收到的字节数。首次写入从 0 开始，后续块连续写入。重发已确认的相同字节会得到当前确认位置，跳跃偏移或改写已有字节返回冲突。读取返回从指定偏移开始的已有字节，读到当前位置末尾返回空字节数组。调用者可逐块等待确认，避免排队发送整个文件。

单块上限为 256 KiB，单会话为 16 MiB，宿主为 64 MiB 和 16 个会话。新会话按声明大小预留预算。句柄属于发起调用的窗口及插件，关闭可重复调用。插件停用通过现有 disposer 关闭，窗口销毁和主窗口启动回收遗留会话。操作超时表示调用方停止等待，显式关闭释放宿主持有的缓冲区。

## IPC

控制参数使用 JSON。写块使用完整的 `Uint8Array` 请求体，句柄和偏移由请求头传递。Rust 从 `tauri::ipc::Request` 读取原始字节。读块使用 `tauri::ipc::Response` 返回字节。兼容 Tauri 回退路径中的有界数字数组，每个值须为 0 至 255 的整数。

`host/schema` 公布能力和限额。现有 `ctx.bytes`、`streamRaw`、JSON 信封版本和 Sidecar 行协议维持其接口。现有 raw RPC 复用超时逻辑、结构化错误和在途统计，并接收有界的回退字节数组。

验收覆盖超过 1 MiB 的分块往返、重复块、并发预算、跨窗口访问、关闭与清理，以及正常字节和 IPC 回退格式。单次 IPC 仍会产生跨进程缓冲和复制。已在磁盘上的大型 Sidecar 输入输出可继续通过文件交接。
