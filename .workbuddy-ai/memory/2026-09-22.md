## 组件工厂原来是 376 层串行瀑布（已修）

日志里新加的**分插件**耗时一跑就指出来：`builtin.notepad 2163ms`，其余插件 <35ms。
**不是 notepad 慢** —— `activate()` 第一件事是 `await loadUiKit()`，
**先激活的插件替所有人付这笔钱**，notepad 只是排第一。

`loadUiKit()` 原本 `for (…) await load()` 逐个加载 376 个组件模块 → 浏览器一次只发一个请求。
改成 `Promise.allSettled` 并行。另把 `loadUiKit()` 移到 `boot()` 开头并给它自己的
`uikit` 标记，否则那行 per-plugin 数字是谎话。

**这是 dev 模式的成本**（生产构建里组件是静态 import，没有瀑布）。

## 护眼插件三项优化（拖拽卡顿 / 休息窗白屏 / idle.exe）

### ① 代理假设被排除（再次实测）

用用户给的 `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy` 清掉代理后启动，
症状**与不清代理时完全一致**：`[host] frontend did not reveal the window within 5s — showing it anyway`、
`grep -c "boot 2026-09-22T08:"` = **0**、9222 从不监听。
**所以代理不是本次白屏的原因。** 与上面那条"代理是干扰因素"并不矛盾 —— 代理能干扰，但清掉它并不足以让我这边稳定；
**可靠路径仍是用户的交互终端**。这条要记住：**别再花时间在我自己的 shell 里复现白屏**。

### ② 拖拽卡顿：不是 idle.exe，是 `backdrop-filter`

- **主因**：透明置顶窗口上的 `backdrop-filter: blur()`（胶囊 8px / 菜单 16px / 按钮 12px / 遮罩 `scrim×10px`）。
  模糊目标包含"该窗口背后的一切"，**拖动主窗口（或任何从胶囊下面经过的窗口）都会让它的 backdrop 每帧变化**
  → 整机发涩；全屏遮罩最糟（覆盖整个工作区 + 穿透 + 全程重合成）。**四处全部删除**，遮罩改纯色 scrim。
- **次因**：`idle.exe` 原本常驻整个会话（4 Hz 轮询 + 每秒 4 条信封过宿主），而 `pauseOnActive`
  只影响**休息倒计时**这一个消费者 → 改为 `wantsIdle()/syncIdle()/stopIdle()`，**只在休息期间运行**，
  `enterRest` 在 `showRest()` **之前**起、`enterWork` 在 `hideRest()` **之前**停
  （放后面会被 300ms 淡出动画延迟释放 —— 测试抓到过）。
- **顺手**：`mountPill` 的 `window.addEventListener('blur', endDrag)` 删掉（`focus:false` 窗口永远拿不到焦点，
  `blur` 只会误触发截断拖拽），换 window 级 `pointerup/pointercancel`。
- 状态行改为**诚实三态**：空闲检测 已关闭 / 待命（工作期，正常）/ 不可用 / 输入中 / 空闲。
  原来的写法把"工作期没采样"报成失败。

### ③ 休息窗白屏几秒：窗口创建时就是 UA 白底

根因：插件窗口在 `pluginwin-host.js` 完成 Blob-import 并调 `mountWindow` **之前**，
页面内容只有用户代理的白色背景 —— 这就是那几秒白屏。

- **所有插件窗口改 `visible:false` 创建**（`visible` 在宿主 `WINDOW_OPTIONS` 白名单里，插件侧可独立完成），
  由 UI 报 `hello` 触发 `show()`；`reveal()` 带 **5s 兜底 show + warn 日志**（功能不能静默消失）。
- `mountLock` 原本**没发 `hello`** → 补上，否则它永远等不到显示。
- **休息窗口提前 `WARM_LEAD_SEC = 20` 秒预热**（`onTick` 里 work 模式剩余 ≤20s 时 `warmRest()`），
  休息结束改 **`hide()` 而非 `close()`** —— 第二次起是热窗口，代价从数秒降到零。
- `mountRest` 删掉挂载时的 `requestAnimationFrame(...add('show'))`：窗口此时是隐藏的，淡入会被浪费，
  导致揭示时直接满不透明弹出；淡入改由 `restShown` 状态驱动。

# 第四轮：六项插件优化（不改本体、不做 git 操作）

用户诉求六条：①主题/字体改真 `select` ②修拖拽卡顿 ③透传命中区与锁图标视觉对不上
④接管悬浮窗右键（取消功能菜单）⑤改计时参数后立即重置 ⑥休息遮罩没盖住任务栏。
两个决策由用户选定：**右键=打开功能菜单并移除 ☰ 按钮**；**改哪个阶段就重置哪个阶段，
并把 autoStart 开关暴露出来**。

### ① 主题/字体改真 `select` —— 受控陷阱

改成 `select-trigger + select-value + select-content + select-item`（与内置 procman 同形，宽 150px）。

**坑（差点写错）**：reka-ui 的 `SelectRoot` 是
`passive: props.modelValue === void 0` —— **一旦传 `modelValue` 就切受控模式**，
显示值只认 prop。而这个配置面板**刻意不重渲染**（每次重渲染会丢数字输入框焦点），
于是受控 Select 会"拒绝"用户的变更。**必须用非受控 `defaultValue`**，
让 Select 自己持有显示值，`renderPanel` 时再把配置回填。两处（主题、字体）都改了，
代码里留了完整注释解释为什么不是 `modelValue`。

### ② 拖拽卡顿 —— 每次 `control` = 2 次 IPC 往返

用户的关键线索：**休息全屏界面下拖其他程序不卡，拖主界面和悬浮窗卡；非休息时也卡**。
根因不在 `idle.exe`（上一轮已把它改成只在休息期跑），而在：
`ctx.windows.control` 每次调用要 **2 次 IPC 往返**（`WebviewWindow.getByLabel()` + setter），
而拖动时胶囊**每帧**都要动，旧代码还**连带动锁窗 + 菜单窗** → 一次拖拽 = **6 次往返/帧**。

**改法**：`case 'move'` 里**只** `moveWin(LABELS.pill, to)`；锁窗/菜单窗等 `live:false`
（拖拽结束）时统一归位一次。新增测试用例 11 锁住这条行为（断言 live 阶段
`position` 调用**只**命中 `L.pill`，结束后顺序为 `[pill, pill, lock, menu]` 并持久化）。

### ③ 透传命中区与锁图标对不上 —— 三处原因

用户观察"实际的按钮控件是一个扁椭圆"。三个原因叠在一起：
1. 锁窗固定 **28×28** 盖在 **22×22** 的图标上 → 多出的 6px 把圆形读成扁椭圆；
2. hover 提示用**外发光** `box-shadow: 0 0 6px` —— 画在窗口**外面**，被窗口边界裁掉；
3. 硬编码的 `lockDx/lockDy` 只是近似，字体/字重一变就漂移。

**改法**：
- 命中区尺寸/位置**由胶囊自己实测上报**：`#lock-visual.getBoundingClientRect()` →
  `send({act:'lock-rect', rect})`，主窗口用这个 rect 定锁窗几何（带计算兜底）。**实测值优先于任何猜测**。
- 锁窗**只在锁定时存在**（`ensureLock` 在 `toggleLock` 与 `showRuntime` 里按需创建，解锁即 `close`）。
- hover 改**内嵌描边** `box-shadow: inset 0 0 0 1px …` —— 画在窗口内，不会被裁。
- 状态订阅里字体变化后 `requestAnimationFrame(reportLockRect)` 重量一次。

浏览器实测：上报 `lockRects` 与真实 `realRect` **完全一致**（`{x:1250,y:419,w:22,h:22}`）。

### ④ 接管右键 —— 移除 ☰

`window.addEventListener('contextmenu', e => { e.preventDefault(); send({act:'toggle-menu'}) })`，
`preventDefault()` 必须的，否则 WebView2 会弹"重载/检查元素"（那不是应用菜单，也没法美化）。
`#lock-visual` 变成可点命中目标并从拖拽里排除（`e.target.closest('#lock-visual')`）。
胶囊 HTML 里删掉 `#btn-menu`。浏览器实测：`ctxPrevented:true`、`ctxStillBubbles:false`、
`toggleMenu:1`、`toggleLock:1`、`togglePause:1`。

### ⑤ 改参数立即重置 + autoStart 开关

`applyTimingReset(before, after)` 接进 `saveConfig`：**只在"改的键 === 当前阶段对应的键"时**
`setRemaining()` 重启该阶段（work 期看 `workMinutes`，rest 期看 `restMinutes`），
并清 `S.paused`。顺带把 `autoStart`（"随应用一起启动"）加进 `SWITCHES` 表并暴露到
**菜单配置页**（四个开关与主窗口共用同一张 `SWITCHES` 表，配置页高度 452→566）。
新增用例 12：`Work: 24:55` 改 `workMinutes:1` → `Work: 01:00`；改 `restMinutes` 不动工作；
休息中改 `restMinutes` → `Rest: 02:00`。

### ⑥ 遮罩盖不住任务栏 —— `avail*` 是工作区

根因：`ensureRest` 用 `screen.availWidth/availHeight`（**工作区，已扣任务栏**）而非整屏。
**改法**：`S.full` = `screen.width/height` **整屏 + 每边 80px 外扩**（`BOX.maskPad`）。
外扩不只是保险 —— 它让"任务栏停在哪条边 / 工作区原点是否偏移"变成**无需回答的问题**。
可行性已确认：窗口允许大于屏幕、允许负坐标、允许盖住任务栏。
用例 5 断言 `1920+160` / `1080+160` / `x=-80` / `y=-80`。

### 新增的两条「坐标/IPC」事实（写进 MEMORY.md）

- **`window.screenX` ≠ 窗口左上角**：`decorations:false` 下仍差约 10px →
  主窗口**无法**反推悬浮窗坐标，只能由该窗口自己量并上报。
- **每次 `ctx.windows.control` = 2 次 IPC 往返**（`getByLabel()` + setter）；
  `gated` 是**同步**函数。**拖动时逐帧搬多个窗口 = 卡顿**。

## ① 胶囊太长 → 宽度改为「内容实测上报」

根因不是宽度常量定错，而是 `#time{flex:1 1 auto}` 让时钟吃掉全部余量：窗口 186 px 而内容
自然宽 **159 px**，中间留了 **35 px 死缝**。改成 `#time{flex:0 0 auto;white-space:nowrap}`，
宽度改由胶囊自己量：把 `time.textContent` 临时换成 `WIDEST_LABEL='Paused: 00:00'`
（**最宽的标签**，否则时钟每跳一次就改窗口），`pill.style.width='max-content'` +
`getBoundingClientRect()` 读一次，再还原 → `win-size` 报给主窗口。

`getBoundingClientRect()` 强制 reflow 但**不绘制**，所以同一个 task 里切换 max-content →
读 → 还原**不会闪**。

## ② 菜单文字竖排 → 根因是 `#menu` 缺 `flex-direction`，不是 writing-mode

`#menu` 在 CSS 里**完全没有规则**，而页面切换写的是 inline `menu.style.display='flex'` ——
`display:flex` 不改 `flex-direction` 就是 **ROW**。7 个菜单项被挤进 174 px 宽，
而 flex 行里的裸文本是**匿名 flex item**，CJK 的 min-content 是**一个字符** → 每行一个字。

修法：`#menu{display:flex;flex-direction:column;gap:0}`，并把切页从 inline `style.display`
改成 **class**（`#card.cfg #menu{display:none}` / `#card.cfg #cfg{display:flex}`）——
让 `display` 与它依赖的 `direction` 同处样式表，不再能脱节。

同族 bug：`#cfg .f span` 与 input 同为 flex 子项，**flex 子项不会收缩到 min-content 以下**
→ label 把 input 顶到行外，被 `#card{overflow:hidden}` 裁掉（症状：配置页输入框"看不见"）。
修法：`span{flex:1 1 auto;min-width:0;overflow:hidden;text-overflow:ellipsis;white-space:nowrap}`
+ `input,select{flex:0 0 auto}`。

## ③ 遮罩显示时拖 toolkit/胶囊卡顿 → 三处合成开销

1. `.ring{animation:spin … infinite}` —— 全屏透明置顶窗口上的**常驻无限动画**让整块表面
   每秒重新合成 60 次，整个休息期都在付。→ 改静态双色环。（与 `backdrop-filter` 同一类代价）
2. `lock-rect` 走 `syncGeometry` → **一个 22 px 图标触发全屏 move+resize**，锁定期间每次
   状态广播都跑。→ 改窄范围 `afterResize()`，`applyMaskRect()` 加**去重**（未变则不 move/size）。
3. 遮罩外扩 `maskPad` 80 → 1920×1080 上得到 2080×1240，**多 25% 透明表面**。→ 降到 **6**，
   并**精确推算整屏 rect**：任务栏厚度 = `width-availWidth` / `height-availHeight`，
   `availLeft/Top >= 厚度` 时回推显示器原点。

另加 **`TOPIC_DRAG` 独立 topic**：`bus.publish` 给**每个订阅者各投递一次**，`eyecare.cmd`
被 5 个窗口订阅 → 每帧拖拽消息 5 次 webview 投递，而只有主窗口会处理。独立 topic 降到 1 次。

## ④ 新增胶囊尺寸配置：`pillScale` / `pillFontSize`

`pillScale`（0.7–1.8，乘算 chrome：高度/内边距/圆点/按钮/锁环）、`pillFontSize`（9–20px）。
两个正交旋钮走同一条 `FIELDS` 表 → **主视图与菜单配置页同时出现**。胶囊 CSS 全改 CSS 变量，
每个变量带 scale 1 的 fallback（首帧即正确，不等 state 到达）。

**刻意不暴露宽度**：宽度由内容实测决定；让用户钉宽度只会钉出一个与文字不符的值。视图里写明
「胶囊宽度由内容实测决定：缩放只影响高度与内边距，字号只影响文字」。

## ⑤ 即时分辨率：`ensureRest()` 先 `readArea()`

每次休息都重读 `screen.*`（`recover()` 也调），所以换分辨率/改缩放/换显示器后下一次休息即生效。
`create` 与 `control('size'/'position')` 都是**逻辑尺寸（DIP）**，与 `screen` 同一单位空间 →
缩放天然一致。任务栏也按逻辑尺寸，两边对齐。

**多显示器是硬限制**：`window.screen` 只描述**当前窗口所在那块屏**，宿主未暴露显示器枚举，
`ctx.windows.control` 没有 `getPosition`，`window.screenX` 也不是窗口左上角（`decorations:false`
下仍差 ~10px）。→ 遮罩完整覆盖主窗口所在的那块屏（含任务栏），第二块屏仍透出。已如实写进 README。

## ⑥ 休息右上按钮窗：根因是「窗口比内容窄」

两个按钮自然宽 **244 px** + padding > 旧窗口 **250×42** → 文字折行 + `border-radius:999px`
→ 每个标签被压成**被切的扁椭圆**。修法：`white-space:nowrap` + `flex:0 0 auto`、
padding `8px 16px`→`9px 18px`，窗口改**实测两轴**（`measure(document.body,{w:true,h:true})`）
→ **254×39**。

## ⑦ 窗口尺寸「内容实测 + 上报」的通用机制（`win-size`）

`measure(node, axes, floor)`（`max-content` + 同步 `getBoundingClientRect`）、
`sizeReporter(bridge, fn)`（**只在测量值变化时发**）、`sizeOf(label, page)`（未上报轴的真值）。
三条关键：

- **必须去重**，否则「量 → 改窗 → 重量」成环。
- **单轴上报意为「这一轴变了」**，另一轴沿用当前值。默认成 0 会让胶囊第一次报宽度时**塌成 0 高**。
- **高度要在钉住的宽度下量**：高度依赖宽度（配置页底部说明 276px 折两行、400px 折一行），
  否则同一内容在不同窗口宽度下量出不同高度（曾实测 `@400→595` vs `@186→579`）。

## 踩过的坑（本轮新增）

- **`const` 不提升**：`mountMenu` 的 subscribe 回调调 `reportSize()`，而 `const reportSize = …`
  写在后面 → **TDZ 让第二次测量静默失败**，高度停在第一次的错误值（`measure` 的 floor `120`）。
- **`overflow-y:auto` 的滚动容器 `max-content` 高度不可靠**（实测**少 ~16px**）→ 配置页保存
  按钮被切。要测量先去掉滚动（`#card{overflow:hidden}` 兜底）。
- **`--force-device-scale-factor=2` 的截图是错的**：它按物理像素设 `--window-size`，等于**缩小
  CSS 视口** → 得到的是另一个布局，不是"放大"。放大截图要用 `transform:scale()` 的中间页。
- **无头 CLI `--screenshot` 不绘制 `type=number` 等表单控件**（`--disable-gpu` 也不画），
  而项目自带 CDP 版 `scripts/shot.mjs` 能画 → **截图工具会骗人，要两种方式交叉验证**。
- 探针页参数**别用 `?state=<json>`**（URL 编码后在 `<script type="module">` 里 `JSON.parse` 报错），
  用 `?preset=` 表。

## 文件访问可行性分析（待用户裁定）

写了 `docs/plugin-dev/FILE-ACCESS-PLAN.md`。**没实现**，因为「默认信任插件」
会推翻本项目唯一一条安全承诺。

**核实的事实**：
- **Tauri v1 的 fs 不是插件，是核心 API**（`@tauri-apps/api/fs` +
  `tauri.conf.json` 的 `allowlist.fs`），v1 **没有** `tauri-plugin-fs`
- v2 现成：`tauri-plugin-fs` **v2.5.2**、`tauri-plugin-dialog` **v2.7.3**
- **拖拽不需要插件** —— `onDragDropEvent` 是核心 API（`@tauri-apps/api/webview`）
- fs 模型是「**权限 + scope 两个都要**」；`fs:default` **只覆盖应用自己的目录**
- **关键结构性事实**：fs 权限按 **window label** 匹配，而**所有插件都跑在主窗口里**
  ⇒ **没有「每个插件各自的文件权限」** —— 本项目唯一做不到「一插件一权限」的地方

**风险论证引了源码**：`lifecycle.js` 的 `adoptNewPlugin` 是**首次发现即启用**
（`known.add` + `enabled.add` + return true）。和宽 fs scope 叠加
= **丢一个文件夹进去就给了一个陌生程序整个 home 的读写权，用户没做过任何同意的动作**。

**三条路线**：A 全信任（可行，但要撤回 `storage.md` 的安全声明）、B 读宽写窄、
C 能力式（推荐 —— 授权来自**用户的一次动作**：拖拽/选择就是同意）。

## 拖拽陷阱（已写进 debugging.md）

`dragDropEnabled` **默认 true**，会**静默压制 HTML5 的 `ondrop`** ——
按 Web 习惯写拖放会「什么都没发生也不报错」。要用 HTML5 拖放必须显式设 `false`。
