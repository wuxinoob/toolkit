## 子进程管理：4 个交互缺陷 + template 并入 profile（737d5b5）

用户报的四个问题，根因各不相同：

1. **profile「+ New」无反应** —— 按钮在面板标题栏，委托监听却绑在 `.pm-profiles`
   （列表）上，列表里没有这个按钮。改为绑 `.pm-profiles-panel`。
2. **sessions 的 kill 无反应**（我上一轮引入的回归）—— `killSession` 走
   `handle.close()`，pty transport 据此发 `Envelope.end(ch)`，但帧处理器只认
   DATA/EXIT/ERR，end 帧被丢弃。进程确实停了，行状态还是 `running`，看着就像
   按钮坏了。补 END 分支。
3. **close tab 会关掉窗口** —— 原名 `closeSessionTab` 把「杀进程 + 删条目」一次
   做完，丢掉正在看的输出。拆成 Stop（停进程、留条目与输出）与 Remove tab
   （删条目，运行中拒绝并提示）。
4. **template 与 profile 重合** —— 确实重合：无定时、无自启的 profile 就是
   template。删掉整套 TEMPLATES（面板 / renderTemplates / onTemplateClick /
   persistTemplates / state.templates），`DEFAULT_TEMPLATES` → `DEFAULT_PROFILES`。

**顺带发现并修掉合并时漏掉的死代码**：表单 `saveTpl` 分支仍在调用已删除的
`persistTemplates()` / `renderTemplates()`，勾选即 TypeError。改成
`upsertProfile`。教训：删函数时静态检查不会报错，只有点到那个按钮才炸。

## 主题切换 + 全部插件迁移到 .tb-*（d5d8fa3）

**主题 = `<html>` 上的一个属性**，不是换样式表：
`:root[data-theme='light'] { --color-canvas: … }`。这是唯一能让 Blob URL 插件
（无法 import 任何东西）被主题化的方式 —— 它们能继承自定义属性。

- `src/host/theme.js`：system/light/dark，system 跟随 prefers-color-scheme；
  localStorage 持久化；跨窗口用 `storage` 事件推送（不是被禁的轮询）。
- `index.html` 内联预置脚本：打包后 CSS 是独立 `<link>`，先于模块生效，
  不预置的话浅色用户每次开窗闪一帧深色。
- 浅色 `--color-brand` 用更深的 #2f6bd8：深色的 #6f9cf5 在白底上做文字对比度不够。

**迁移中两个不能继承的特例**：
- **xterm 是 canvas**，必须给具体对象。`readTermTheme()` 从 document 读 token
  构造，并订阅主题变化重新着色。这是唯一一处 token 被复制进 JS 的地方。
- **透明窗口**（floatwin）需要 alpha，用
  `color-mix(in srgb, var(--color-surface) 97%, transparent)`，零 JS 跟随主题。

**新增设计系统原语**：`.tb-list/.tb-row`（状态用 `aria-selected`，不另设修饰类）、
`.tb-pane`、`.tb-tabs/.tb-tab`、`.tb-icon-btn`、`.tb-dot`、`.tb-t-*`（意图文字色）、
`.tb-screen`（全屏接管，替掉 eyecare 写死的深色遮罩）、`.tb-markdown`（渲染后的
Markdown 没有类可挂，只能作用域元素选择器）、`.tb-input-inline`。

## 机制

插件在 manifest 里声明想改哪些设计令牌，分主题：

    "contributes": {
      "theme": {
        "dark":  { "--color-brand": "#a78bfa", "--color-brand-hover": "#bda4ff" },
        "light": { "--color-brand": "#6d3fc4", "--color-brand-hover": "#5c33ac" }
      }
    }

宿主（`src/host/pluginTheme.js`）变成每个主题一条作用域规则：

    :root[data-theme='dark']  [data-plugin='x'] { --color-brand: #a78bfa; }
    :root[data-theme='light'] [data-plugin='x'] { --color-brand: #6d3fc4; }

**两套主题都提前生成，靠 data-theme 属性选择** —— 和应用自己的令牌完全一样的机制，
主题切换时不需要任何 JS 重新注入，也就没有需要同步的状态。

作用域来源：`ViewHost` 给视图挂载点设 `data-plugin`、`ctx.ui.mountOverlay` 给 overlay
内容设、插件窗口设到 `<html>` 上（`[data-plugin='x']` 匹配任何元素，含根元素，所以
一条选择器覆盖三种场景）。

## 为什么值校验长这样（这是安全的核心）

CSS 声明以 `;` 或 `}` 结束，`<style>` 元素以 `<` 结束。所以 `validValue` 直接拒绝
`; { } < > \ @` 和换行 —— **这些字符一旦不在，就无法终止声明去写自己的规则**，
值只能是值。其余（hex / rgb() / oklch() / color-mix() / var()）都可以放行。

在此之上额外拒绝 `url(`、`image-set(`、`expression(`、`-moz-binding(`，尽管它们的
字符集能过。**`url()` 是真正要紧的那个**：它把颜色令牌变成对任意主机的请求，
是加了步骤的追踪信标，而主题根本不需要它。

坏贡献**只报告不致命**（进插件日志，落到 debug.log）：因为失败模式是静默的 ——
令牌名写错，插件只是"看起来正常"。
