## 插件生命周期：已有的是完整的，但「窗口」那块没人回收

用户问：有没有插件生命周期管理 / 能不能手动关掉正在跑的插件（前后端）/ 有没有现成接口。

**查下来答案**：生命周期管理**已经有了**，而且后端是真的关：

| 资源 | 谁回收 | 时机 |
|---|---|---|
| 订阅 / 热键 / 主题 / 视图 | 宿主（`deactivate`） | 停用 |
| streams / sidecars / ptys | 宿主（`disposer.track(() => h.close())`） | 停用 |
| **窗口** | **没有人** ← 缺口 | — |

**`ctx.windows.create` 是唯一没有 `disposer.track` 的资源获取点。** 停用一个建过窗口的
插件后，那些窗口留在屏幕上**没人能关** —— 插件的 JS 上下文已经没了，托盘只认识 `main`。
插件自己在 `deactivate()` 里关当然可以（eyecare 就关），但那是靠自觉，而**其他每一种资源
都是宿主强制回收的**。

**修**（`170a314`）：`create` 把窗口交给 disposer。**只回收本次真正创建的** ——
label 已存在（复用）的那个可能是别的插件建的，替它关掉就是另一个方向的 bug。

**新增 `tests/window-teardown.test.mjs`**：shim `window.__TAURI_INTERNALS__` 而不是 stub
API 模块（理由写在 `browser-stubs-loader.mjs`：真实的 `@tauri-apps/api` 只是那个全局的
薄包装，stub 模块会把被测的那一层也换掉）。**已实测：移除 track 会让测试失败。**
另外它是**独立文件** —— `window-options.test.mjs` 的用例依赖「没有宿主」，
在那里装 shim 会改变它们的含义。

## 新增 `host/stop_session {plugin, ch}`（host-only）

设置页的 live sessions 列表**只读**，而 `stream/close` 是按**调用者的插件 id** 定位的
（`session::stop_one(plugin, ch)`）—— 宿主以 `__host__` 的身份**永远匹配不到插件的会话**。
对插件来说那个 keying 是**对的默认值**（一个插件不该停别人的活），所以宿主需要自己的门。

**必须 host-only**：`rpc:host` 是发给插件的，而 `host` 此前只有读动作（`info`/`sessions`/
`plugins`/`schema`）加一个日志写。`stop_session` 会杀别人的进程 → 和 `unregister` 一样按
宿主身份门禁。**一个读授权悄悄变成写权力，正是权限模型腐烂的方式。**

**`unregister` 之前也没被测试覆盖** —— 现在一条测试同时盯这两个动作的门禁
（`tests/host-kernel.test.mjs`）。

## 可见性：从「插件是 active」到「插件在跑什么」

- **插件表新增 `Running` 列**：每个插件当前开着几个 endpoint（sidecar / stream / pty），
  数据来自宿主那份统一会话表。`active` 说的是代码在跑，这一列说的是**它在跑什么**；
  **停用后归不了零，就是泄漏第一次变得可见**。
- **会话行**：加 kind 徽章 + `Stop` 按钮；空列表给一句说明而不是空白。
- 停用/启用后自动刷新会话表，否则 Running 列是旧的。

## 删掉 Settings 里遗留的「Plugin settings」卡片（`3415e8d`）

用户看到的那块「Plugin settings / Forms declared by plugins via contributes.settings. /
Hello / Enable this plugin to edit its settings.」是**遗留**。删之前查了三件事：

- **本仓库没有任何插件声明 `contributes.settings`**（`src/plugins/`、`examples/` 都没有）
- **文档从没提过它**（`docs/` 里零命中）
- **插件侧的那一半零使用**：`ctx.onSettingsChanged` 只订阅一个由本文件 `saveField`
  发出的 `settings:changed:<id>`，而没有任何插件订阅它

唯一声明它的是**已安装的 `hello.demo`** —— 早几轮的遗留，**源码已经不在仓库里了**。
所以这张卡片存在的意义，就是给一个不再随仓库发布的插件渲染一张表单。

**删了**：模板整张卡；脚本 `forms`/`loadForms`/`saveField`/`pluginsWithForms`/`optionValue`/
`optionLabel` + `onMounted` 里的调用 + `watch(...)`；随之变成未使用的导入
（`Checkbox`/`Label`/`Select*`/`Separator`/`events`/`watch`）；以及 `ctx.onSettingsChanged`。

**留下的形态才是对的**：插件自己的设置归插件 —— `ctx.storage` 是按插件命名空间的、
永远可用，插件在自己的视图里画控件、自己持久化（`eyecare` 就是这么做的）。
**两处都留了说明注释**（「查过什么、为什么删」），避免被当成漏掉的 TODO 重新加回来。

## ⚠️ 又踩了一次：`git commit -m "…反引号…"` 会被 bash 当命令替换

提交信息里我写了 `` `contributes.settings` `` 这类带反引号的词 —— **bash 在双引号里会执行
命令替换**，于是消息被吃掉一大半，还混进了 `vol` 的输出。提交**内容是对的**，只有消息坏了，
用 `git commit --amend -F <文件>` 修好（内容不变）。

**这是同一个坑第二次**（上次是 `python -c` 里的反引号）。**硬规则：任何含反引号/`$` 的
文本要写进文件，再用 `-F` / `-m` 读文件，永远不要直接放进 `-m "..."`。**
判断标准很简单：**这段文本会不会经过 bash？** 会 → 用文件。
