## 修复：定时间隔任务在待机唤醒后死循环（procman）

- 根因：`dueAt(interval)` 从 `lastFired` 算（睡醒时落在过去）→ `armSchedules` 变 0ms 定时器 →
  触发时进程还活着 → `launchProfile` 提前 return 且**不写 `lastFired`** → 槽位仍过期 → 0ms 再来一次。
  状态不变 = 忙循环，一次迭代一个 `"X" is already running` 提示。
- 改动 `src/plugins/procman.js`：
  - `lastFired` 提到 `launchProfile` 最前面（所有提前 return 之前）——「触发即消费槽位」。
  - `armSchedules` 改用 `scheduleDelay()`；`clearSchedules` 拆出 `clearScheduleTimers`（重挂定时不再吞掉待执行的 restart）。
  - 定时触发撞上「已在跑」只记日志，**只有手动 Run 才弹提示**。
  - debug 句柄加 `launch(profileId, reason)`，让「启动已有 profile」这条路径可测。
- 改动 `src/plugins/procman-supervisor.js`：新增 `scheduleDelay()` + `MIN/MAX_SCHEDULE_DELAY_MS`
  （延迟夹在 [1s, 2^31-1]）；`dueAt` interval 再夹 `now + every`（时钟回跳不会让调度停摆）。
- 新增 `tests/procman-schedule.test.mjs`：MockTimers 驱动真插件模块，11 分钟墙钟断言触发次数 ≤ 12
  （缺陷版本实测 601 次，已手工验证会变红）。`procman-supervisor.test.mjs` 补 4 条纯函数测试。
- `src-tauri/src/lib.rs`：托盘右键菜单加「重启应用」，走 `app.request_restart()`（`app.restart()` 在主线程跳过
  `RunEvent::Exit` → `kill_all()` 不跑 → 孤儿进程）。`tests/window-options.test.mjs` 加了这条断言。
- 全量 `node --test` 310 项通过；`cargo check` 通过。
